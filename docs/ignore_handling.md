# IGNORE HANDLING

WHAT GETS EXCLUDED FROM A SCAN IS AS IMPORTANT AS WHAT GETS COUNTED. THE
SCANNER APPLIES THREE LAYERS OF FILTERING, IN ORDER.

## LAYER 1: BUILT-IN NOISE DENYLIST

A FIXED LIST OF PATTERNS THAT NEVER BELONG IN AN LLM CONTEXT WINDOW, APPLIED
REGARDLESS OF ANY IGNORE FILE:

- VENDOR AND DEPENDENCY DIRECTORIES — `node_modules/`, `vendor/`, `third_party/`
- BUILD OUTPUT — `dist/`, `build/`, `out/`, `.next/`, `target/`, `coverage/`
- VCS AND CACHE METADATA — `.git/`, `.venv/`, `__pycache__/`, `.turbo/`
- LOCKFILES — `package-lock.json`, `yarn.lock`, `Cargo.lock`, `poetry.lock`
- MINIFIED ASSETS AND SOURCEMAPS — `*.min.js`, `*.map`
- BINARY AND MEDIA FILES — IMAGES, ARCHIVES, FONTS, AUDIO, VIDEO, DATABASES

THE FULL LIST LIVES IN `BUILTIN_IGNORES` IN `src/scan.ts`.

## LAYER 2: IGNORE FILES

THREE FILENAMES ARE READ AT THE SCAN ROOT AND IN EVERY SUBDIRECTORY:

| FILE | PURPOSE |
| --- | --- |
| `.gitignore` | THE STANDARD GIT IGNORE RULES |
| `.tokenignore` | TOKEN-COST SPECIFIC EXCLUSIONS |
| `.ignore` | THE GENERIC IGNORE CONVENTION |

NESTED FILES APPLY ONLY TO THEIR OWN SUBDIRECTORY AND BELOW, MATCHING GIT
SEMANTICS. PATTERNS ARE EVALUATED WITH THE `ignore` PACKAGE, SO FULL GITIGNORE
SYNTAX IS SUPPORTED — INCLUDING NEGATION, ANCHORING, AND DIRECTORY-ONLY
RULES.

`.tokenignore` IS THE RIGHT PLACE FOR EXCLUSIONS THAT SHOULD NOT AFFECT GIT:

```
# never send these to a model
docs/architecture/
*.stories.tsx
```

## LAYER 3: FILE-LEVEL GUARDS

AFTER IGNORE RULES, EACH REMAINING FILE IS CHECKED INDIVIDUALLY:

- FILES LARGER THAN THE MAXIMUM SIZE ARE SKIPPED AS `too-large` (DEFAULT 5 MB)
- EMPTY FILES ARE SKIPPED AS `empty`
- BINARY FILES ARE SKIPPED AS `binary` — DETECTED BY A NULL BYTE IN THE FIRST
  8 KB
- SYMLINKS ARE SKIPPED AS `symlink`, TO AVOID FOLLOWING LINKS OUTSIDE THE REPO
- UNREADABLE FILES ARE SKIPPED AS `unreadable` RATHER THAN ABORTING THE SCAN

SKIPPED FILES ARE COUNTED AND SUMMARISED IN THE REPORT AND IN THE JSON OUTPUT.

## DISABLING IGNORE FILES

SCAN EVERYTHING, INCLUDING VENDORED AND GENERATED CODE:

```sh
shrink . --no-ignore
```

THE BUILT-IN DENYLIST STILL APPLIES IN THIS MODE, WHICH KEEPS THE SCAN FROM
CHOKING ON A 40 MB `node_modules` TREE.

## SUGGESTED IGNORES

THE REPORT ALSO PROPOSES PATTERNS FOR FILES THAT WERE SCANNED BUT PROBABLY
SHOULD NOT BE IN AN AGENT'S CONTEXT — LOCKFILES, TEST SNAPSHOTS, SOURCEMAPS,
GENERATED CODE, VENDORED DIRECTORIES, COVERAGE REPORTS, LARGE CSV AND NDJSON
DUMPS, LARGE JSON BLOBS, NOTEBOOK OUTPUT CELLS, AND TRANSLATION CATALOGS.

EACH SUGGESTION SHOWS:

- THE PATTERN TO ADD
- THE TOKENS IT WOULD FREE
- THE NUMBER OF FILES IT MATCHES
- WHY IT IS USUALLY SAFE TO DROP

SAVINGS NEVER DOUBLE-COUNT: EACH FILE IS MATCHED BY THE FIRST RULE THAT
APPLIES.

TO APPLY A SUGGESTION, ADD THE PATTERN TO `.tokenignore` AND RESCAN.

## ORDERING NOTE

IGNORE FILES ARE COLLECTED AS THE WALK DESCENDS, SO A ROOT-LEVEL
`.gitignore` IS LOADED BEFORE ITS SUBDIRECTORIES ARE VISITED. NESTED IGNORE
FILES ARE COLLECTED ON ENTERING THEIR DIRECTORY, BEFORE ITS ENTRIES ARE
READ.
